# FBT UI Alignment Plan

**Plan file:** `.kilo/plans/1788338150133-fbt-ui-fix-plan.md`
**Scope:** Wire fringe-benefit entry, persistence, and display through the Payroll page, payslip, dashboard, and reports. No changes to `fbt-engine.ts` or `payroll-engine.ts` core logic.
**Out of scope:** New dedicated FBT quarterly-return page, Prisma migration for expanded `FringeBenefit` columns (flagged as follow-up).

---

## Decision Locked

- **Fringe-benefit entry pattern:** Per-row "Add Fringe Benefit" button → modal form per employee. Benefits render as inline chips with a remove button. Confirmed by user.
- **Frozen columns:** Emp ID, Employee Name, Department freeze horizontally using CSS `position: sticky` with calculated `left` offsets. Confirmed by user.
- **No engine changes:** `fbt-engine.ts` and `payroll-engine.ts` are already correct. All fixes are in pages, API routes, and the Prisma schema.

## Task 2 — Freeze First Three Columns

**File:** `src/app/payroll/page.tsx`

Apply sticky positioning to the first three header and body cells.

Column widths (from existing `w-*` classes):
- Emp ID: `w-24` = 6rem = 96px
- Name: `w-40` = 10rem = 160px
- Department: `w-28` = 7rem = 112px

Cumulative offsets:
- Col 1 left: `0`
- Col 2 left: `6rem`
- Col 3 left: `16rem`

Add a `<style>` tag (via `useEffect` injecting a `<style>` element, matching the existing print-style pattern) or add a CSS module. Inline-style approach via Tailwind arbitrary values:

**Header row (`<thead>`):**
```tsx
<th className="w-24 sticky left-0 z-20 bg-gray-50">Emp ID</th>
<th className="w-40 sticky left-[6rem] z-20 bg-gray-50">Name</th>
<th className="w-28 sticky left-[16rem] z-20 bg-gray-50">Department</th>
```

**Body rows (`<tbody>`):**
```tsx
<td className="sticky left-0 z-10 bg-white">...</td>
<td className="sticky left-[6rem] z-10 bg-white">...</td>
<td className="sticky left-[16rem] z-10 bg-white">...</td>
```

**Corner cells** (header AND body first cell) need `z-30` to sit above both the header strip and the frozen column strip. Apply `sticky top-0 left-0 z-30 bg-gray-50` to the Emp ID `<th>`. The other two header cells get `z-20` (below corner, above body). Body frozen cells get `z-10`.

Background colors are critical: without `bg-white` / `bg-gray-50`, transparent sticky cells will let scrolling content show through.

The `overflow-x-auto` wrapper on the table container is already present — no change needed there.

## Validation Plan

1. **Unit tests pass:** `npm run test` — no existing tests should break.
2. **Manual payroll flow:**
   - Open Payroll page, select a period.
   - Click "Add Fringe Benefit" for one employee, enter a motor-vehicle benefit (original cost MWK 30,000,000). Confirm the FBT Base shows MWK 4,500,000 and FBT shows MWK 1,350,000 at 30%.
   - Add a second benefit type (e.g., housing) for the same or different employee. Confirm both appear as chips.
   - Click "Calculate" — confirm FBT columns update live.
   - Click "Save Payroll" — confirm success toast.
3. **Payslip:** Open the saved employee's payslip. Confirm the Employer Contributions section shows the per-benefit breakdown with rule names and taxable values.
4. **Dashboard:** Navigate to Dashboard for the same period. Confirm Total FBT KPI matches payroll total. Confirm the monthly trend chart has an amber FBT area. Confirm the department bar chart has an amber FBT bar.
5. **Reports:** Generate Statutory Summary — confirm Total FBT Base and Total FBT both appear. Generate Payroll Register — confirm FBT Base and FBT columns are populated.
6. **Frozen columns:** Scroll the payroll table horizontally — confirm Emp ID, Name, Department remain visible.
7. **Edge case — no benefits:** Run payroll for employees with no fringe benefits. Confirm FBT columns show 0.00, payslip does not render the benefit breakdown section.
8. **Edge case — excluded benefit:** Add a SCHOOL_FEES benefit with `paymentMethod: CASH_TO_EMPLOYEE`. Confirm it shows as "Excluded" in chips with 0.00 taxable value and does not contribute to FBT Base.
