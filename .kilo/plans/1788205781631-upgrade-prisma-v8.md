# Plan: Upgrade Prisma to v8 — Reality Check

## Critical Finding: v8 is NOT an upgrade of the classic Prisma ORM

The `prisma` npm package at v8 (`8.0.0-rc.12`) is the **Prisma Developer Platform CLI** — a completely different product from the classic Prisma ORM. It does NOT provide `prisma generate`, `prisma db push`, or any of the classic commands.

## What v8 Actually Provides

| Classic Prisma (v5) | Prisma Platform (v8) |
|---------------------|----------------------|
| `prisma generate` | Does NOT exist |
| `prisma db push` | `prisma db update` (requires contracts, not schema files) |
| `prisma migrate dev` | `prisma migration` family |
| `prisma seed` | Not available |
| `@prisma/client` | `@prisma/orm-postgres/runtime` (different API) |
| `schema.prisma` | `contract.prisma` (different syntax) |
| Direct SQL-like queries | Contract-based typed queries |

## What `prisma orm init` Does

Running `prisma orm init --yes --target postgres --authoring psl` on this project would:
1. Create `prisma.config.ts`
2. Move/create `src/prisma/contract.prisma` (new v8 syntax)
3. Create `src/prisma/db.ts` (new runtime import)
4. Add `"type": "module"` to `package.json`
5. Overwrite `.env.example`
6. Modify `tsconfig.json`
7. Require rewriting ALL code that uses `@prisma/client`

## The Problem

The user's codebase has ~15+ files importing `@prisma/client`:
- `prisma/seed.ts`
- All API routes in `src/app/api/`
- `src/lib/payroll-engine.ts`
- etc.

Migrating to v8 would require rewriting every single one of these to use `@prisma/orm-postgres/runtime` with a completely different API.

Additionally:
- `@auth/prisma-adapter@2.11.3` has a peer dependency conflict with `@prisma/client@8.1.0-dev.1`
- The new schema syntax (`TimestamptzString`, `temporal.updatedAtString()`) is incompatible with the existing `schema.prisma`

## Options

### Option A: Full v8 Migration (Massive Rewrite)
- Run `prisma orm init` to set up new project structure
- Rewrite `prisma/schema.prisma` → `src/prisma/contract.prisma` in v8 syntax
- Rewrite all imports from `@prisma/client` → `@prisma/orm-postgres/runtime`
- Rewrite all database queries to use new contract-based API
- Remove or replace `@auth/prisma-adapter` (incompatible with v8)
- Rewrite `prisma/seed.ts` to use new runtime
- Update all API routes, services, and components
- Estimated effort: **Full data layer rewrite**

### Option B: Latest Classic Prisma (v5.22.0)
- Keep `prisma@5.22.0` and `@prisma/client@5.22.0`
- Keep existing `schema.prisma` syntax
- Keep existing scripts: `prisma generate`, `prisma db push`
- Keep `@auth/prisma-adapter` compatibility
- No code changes needed
- `npm run db:setup` works as-is
- This is the **latest stable version of the classic Prisma ORM**

### Option C: Latest Classic Prisma (v6.x)
- Check if `prisma@6.x` classic exists (it may not — the `prisma` package may have been fully replaced by the platform CLI at v6)
- If available, same benefits as Option B

## Recommendation

**Option B** is the correct choice if the goal is to make `npm run db:setup` work with minimal changes. The `prisma` package at v8 is a different product. The "latest version" of the classic Prisma ORM is v5.22.0.

If the user explicitly wants the Prisma Developer Platform (v8), then Option A is required, but it's a full migration, not an upgrade.

## Validation

- Option B: `npm run db:setup` works immediately
- Option A: Weeks of rewrite work, then `prisma contract emit` + `prisma db update` workflow
